# OIHK Basic update architecture

## User contract

Update checks are enabled by default in the desktop application, but they only check availability. OIHK Basic never downloads or installs silently. The user must choose **Download and install**, may cancel while it is safe, and must separately choose **Restart and update** after the signed package and database backup are ready.

The updater states are `checking`, `current`, `available`, `downloading`, `verifying`, `preparing_backup`, `ready_to_restart`, `installing`, `deferred`, and `error`. Release notes, publication date, total bytes when supplied, and download progress are shown in Settings and About.

Cancellation of an active HTTP transfer is best-effort because Tauri does not expose an abort signal. Closing the updater resource guarantees that OIHK Basic does not call installation after cancellation.

## Mandatory signature

The desktop uses the official Tauri 2 updater plugin. `updater:default` is the only added updater capability. Release builds set `bundle.createUpdaterArtifacts=true`, embed the public key, and use an HTTPS endpoint generated by `scripts/generate_release_config.py`.

`Update.download()` verifies the Minisign signature before it returns. An absent, malformed, or invalid signature prevents backup preparation and installation. Checksums in `release-manifest.json` are an additional publication and operator control; they do not replace the mandatory updater signature.

The production private key is never stored in the repository, a build artifact, application data, or a temporary project file.

## Pre-update database protocol

Before restart, the backend:

1. Rejects new `POST`, `PUT`, `PATCH`, and `DELETE` requests with a retryable `503`.
2. Waits up to 30 seconds for active mutating requests to finish.
3. Runs `PRAGMA wal_checkpoint(TRUNCATE)` and refuses to continue while SQLite reports busy.
4. Uses the SQLite online backup API.
5. Runs `quick_check` and `integrity_check` against the backup.
6. Calculates SHA-256 and writes atomic metadata containing source version, target version, UTC date, schema version, byte size, hash, backup identifier, and backup filename.
7. Issues a random one-use shutdown token. Only that token can stop the loopback sidecar.

Backups are stored under `%APPDATA%\OIHK-Basic\backups\pre-update\`. Migration backups use `backups\migrations\`. Evidence and older backups remain outside the installation directory and are not touched by NSIS.

## Migrations and startup recovery

`schema_migrations` records a monotonically increasing version, immutable name, checksum, and application time. A checksum mismatch or failed statement aborts startup. Pending migrations receive a verified backup before any schema statement runs.

Recovery facts are stored at `%APPDATA%\OIHK-Basic\updates\last-update.json`. It contains no case content, credentials, URLs, or exception dumps. Settings/About can open the fixed backup directory, continue with the current version, retry an update, or direct the user to manual recovery.

If migration fails:

1. Close OIHK Basic and preserve the current `oihk-basic.db`, `-wal`, and `-shm` files as a separate incident copy.
2. Verify the selected backup SHA-256 against its adjacent `.metadata.json`.
3. Open the backup with SQLite and require `PRAGMA integrity_check` to return `ok`.
4. Move the failed database set aside; do not overwrite the only copy.
5. Copy the verified backup to `oihk-basic.db`.
6. Reinstall the previous signed version or a corrected newer version, then start and re-check cases, evidence references, reports, Copilot history, settings, and sources.

Automatic rollback is intentionally unavailable: choosing a backup is a custody-sensitive, potentially destructive decision.

## Privacy and logs

There is no updater telemetry. Sanitized local events are rotated in `%APPDATA%\OIHK-Basic\logs\updater.log`. Logged fields are limited to stage, source version, target version, and a stable error code. Paths, investigation content, evidence names, tokens, signatures, and credentials are not logged.

## Endpoint reachability

The configured alpha endpoint is:

`https://github.com/Broskigx/OIHK-Basic/releases/download/basic-alpha/latest-alpha.json`

Installed clients have no GitHub token, so the metadata and every artifact it references must be downloadable anonymously. `Broskigx/OIHK-Basic` is public, which satisfies that: this was previously the blocking condition and no longer is. Serving `latest-alpha.json` and the signed artifacts from a public HTTPS static host remains an equally valid alternative.

The application must never embed a repository token to work around this boundary. If the repository is ever made private again, promotion has to stop until the artifacts are served from somewhere anonymous — a client that cannot read the metadata cannot distinguish "no update" from "cannot reach the channel".

What blocks promotion today is simpler: no release has been published, so no channel metadata exists to point at.
